## ЧТО надо сделать

### Задача 4 — Вернуть плашку вокруг "МЕНЮ", но без оранжевого ореола

Сейчас в PNG я залил коричневым весь регион плашки (y=20..32, x=20..148),
из-за этого надпись "МЕНЮ" висит на голом коричневом фоне без рамки.

Пользователь хочет:
- Плашка-табличка ВОКРУГ "МЕНЮ" должна вернуться (визуально — узкая
  орнаментальная рамка с белым текстом внутри).
- Оранжевого "halo" от MC font-shadow быть НЕ должно.

**Это противоречие**: любая орнаментальная плашка, нарисованная в том же PNG,
что и текст, будет порождать font-shadow вокруг неё. Возможные подходы:

#### Подход A — Сделать плашку плоской/одноцветной
Нарисовать плашку только тёмно-коричневым (без оранжевых пикселей).
Тень от тёмно-коричневого почти не видна на коричневом фоне.
**Плюс**: остаётся в одном PNG, не надо менять архитектуру.
**Минус**: выглядит примитивно (нет блика, нет металлической рамки).

#### Подход B — Сделать плашку «вдавленной» (inset)
Нарисовать тёмный прямоугольник 1px рамкой ниже+правее (имитация
font-shadow), сама заливка плашки чуть темнее общего фона.
Тогда MC font-shadow усилит уже имеющуюся тень — будет выглядеть как
вдавленная панель.
**Плюс**: красиво, не лезет в архитектуру.
**Минус**: рассчитать пиксели в духе MC font shadow надо точно.

#### Подход C — Разделить текст и плашку
Плашку оставить в PNG, а сам белый "МЕНЮ" вывести отдельной командой через
доп. шрифтовой провайдер ИЛИ через `<font>` тэг в menu_title.
MC shadow тогда будет ТОЛЬКО под буквами, не под плашкой.
**Плюс**: чистое разделение.
**Минус**: требует переделать менюшный glyph (убрать "МЕНЮ" из PNG,
добавить отдельный шрифт `bold_white_text`).

#### Подход D — Использовать NMS/protocol hack для отключения shadow
Через ProtocolLib подменять `RenderText` событие для конкретных глифов.
Это сложно и требует написания плагина.
**Минус**: много кода, надо тестировать на 1.16.5.

#### Рекомендуемый подход для следующей сессии: **B**, потом **C** если B не зайдёт.

### Задача 5 — Довести позиции ячеек до пикселя

В прошлой сессии я перерисовал ячейки по формуле:
```
mc_x  = -1 - shift_px + col * 18      (mc-координата относительно glyph origin)
mc_y  = 36 + row * 18
png_x = mc_x / scale                   где scale = height_px / 256
png_y = mc_y / scale
cell_size_px = 16 / scale              (16 mc-pixel = размер видимой части слота)
```

Параметры:
- `shift_px` — суммарный сдвиг от Tamil shift-глифов в menu_title.
- `height_px` — параметр `height` глифа меню в `default.json` (для menu.png = 280, для остальных = 268).

Если предметы всё ещё съезжают:
- Возможно, базовое смещение по Y нужно подкрутить (сейчас 36, попробовать 34, 35, 37, 38).
- MC рисует baseline текста на `chest_y + 13`, верх глифа в `baseline - ascent`.
  Ascent в menus_overlay.yml = 32. Поэтому верх глифа = `chest_y - 19`.
  Чтобы получить mc_y слота относительно верха глифа: `(17 + row*18) - (-19) = 36 + row*18`.
- Также возможна ошибка из-за rounding при `int(round(mc_y / scale))`.

**Что попробовать**:
1. Залить тестовый PNG где КАЖДЫЙ слот сундука помечен явным крестиком в центре.
2. Открыть меню в игре, поместить в слот фактический предмет, замерить
   смещение в скриншоте (в game-pixel'ах) и обратно вычислить дельту.
3. Подкрутить base_y_mc или base_x_mc.

## Ключевые знания о MC 1.16.5 bitmap fonts

1. **Font shadow**: MC автоматически рисует тень = (R*0.25, G*0.25, B*0.25) со
   сдвигом +1, +1 пиксель. Это для бипмап-провайдеров отключить **нельзя** в
   1.16.5 (в 1.20+ можно `"shadow": false`).

2. **Shift-глифы** (для сдвига курсора): используются Tamil символы с
   отрицательным `height`. Эффективный сдвиг = `height + 2`.
   - `௧` U+0BE7 h=-3 → сдвиг -1
   - `௨` U+0BE8 h=-4 → -2
   - `௩` U+0BE9 h=-6 → -4
   - `௪` U+0BEA h=-10 → -8
   - `௫` U+0BEB h=-18 → -16
   - `௬` U+0BEC h=-34 → -32
   и т.д. (степени двойки)

3. **Меню-глифы**: один большой 256×256 PNG, рендерится с `height=268`
   (или 280 для menu.png) и `ascent=32`. Это значит:
   - Высота рендера = 268 mc-пикселей
   - Верх глифа = `baseline - ascent` = `(chest_y + 13) - 32` = `chest_y - 19`
   - PNG пиксель → mc координата: умножить на `(height / 256)`

4. **Координаты слотов сундука**: для каждого slot N в сундуке шириной 9:
   - row = N // 9, col = N % 9
   - Левый-верхний угол слота в mc-координатах от верха сундука:
     `(7 + col*18, 17 + row*18)`
   - Размер видимой ячейки слота: 16×16 mc-пикселей
   - Между ячейками 2 mc-пикселя (поэтому шаг 18).

5. **Заголовок сундука**: курсор начинается на `(chest_x + 8, chest_y + 13)`
   (этот +8 и есть базовое смещение DM-title). shift-глифы сдвигают курсор
   ВЛЕВО, потом большой меню-глиф рисуется от текущего курсора.

6. **Чтобы меню по центру**: чтобы видимая часть меню (PNG x=0..167) попала
   в центр сундука шириной 176:
   - Render width = 167 * (height/256). Для h=268: 174.8 mc-px. Для h=280: 182.7 mc-px.
   - Cursor_x = chest_x + 8 + shift_px
   - Чтобы center видимого попал в chest_x + 88:
     `8 + shift_px + render_w/2 = 88` → `shift_px = 80 - render_w/2`
   - Для h=268: shift_px = 80 - 87.4 = **-7.4** (близко к -8 ✓)
   - Для h=280: shift_px = 80 - 91.3 = **-11.3** (близко к -12 ✓)
