## 4. Why `<font:minecraft:banners>...</font>` does NOT work in DeluxeMenus 1.14.1 on Paper 1.16.5

Verified by elimination, in order:
1. Plain text title `"DEVIN_TEST_123"` → renders verbatim → DM **does** read the YAML.
2. `<font:minecraft:banners>TESTGLYPH</font>` → renders as plain `TESTGLYPH` → the font wrapper is **stripped during MiniMessage→legacy serialization** before reaching Bukkit's inventory API.
3. Raw codepoint without any tag (`"PRE\uF001POST"`) → renders as `PRE□POST` (missing-glyph) → **the codepoint passes through**, only the font attribute is lost.
4. Putting the providers into the **default font** (`default.json`) → renders the bitmap → confirmed working.

Root cause: `Bukkit.createInventory(holder, size, String title)` accepts a legacy `String` only. Adventure `Component.font(...)` is dropped when DM 1.14.1 serializes back to legacy `&`-codes. Paper has a `Component`-aware overload, but DM 1.14.1 doesn't use it.

**Practical rule**: on this stack, never rely on `<font:...>` in `menu_title:`. Always force glyphs into `minecraft:default`.

## 5. Diagnosis of the CURRENT visible issue

User sent screenshot of `/donate` (5-row chest, title `ПРИВИЛЕГИИ`) and said «текстура взади меню вообще че то» — "the texture behind the menu is just something". The bitmap renders the title strip correctly (ornate corner curls + cropped banner ribbon with the per-menu Russian word baked into the PNG) and the orange/black border glass-pane items still fill columns 0 and 8. But the central 7×N slot area still shows the vanilla grey 9-column inset grid showing through the dark fill of the PNG.

### Why?
Minecraft renders the chest GUI in this order:
1. Chest GUI texture (`generic_54.png`) — light grey background **and** the recessed slot bezels.
2. Item icons inside slots.
3. Inventory title text (= our glyph).

Steps 1 and 2 paint the central slot area **on top of** any glyph pixels that fall in that region. Even though our 168×107 PNG with `ascent=13` does extend into the slot area on paper, that part of the glyph is overpainted by the chest texture's slot bevels every frame. So in practice **a font glyph can only realistically style the title strip** (≈18 px tall) and a thin margin to its left and right; it cannot replace the slot grid.

What we are currently relying on for the side borders is **DM filler items** (`orange_stained_glass_pane`, `black_stained_glass_pane`) in slots 0 and 8 of each row — that's why those columns appear orange/black. The inner 7 columns still show whatever item (or empty vanilla slot) DM placed there.

## 6. The correct architecture (what the YouTube reference actually does)

From the linked tutorial (Джейкоб, 2023-06-09):
> "Весь принцип заключается в том что мы должны наложить собственное изображение поверх меню и выровнять его четко посередине. Чтобы меню было кликабельным нам необходимо под каждой кнопкой установить предмет... Благодаря ресурс-паку с кастомными моделями мы делаем эти предметы невидимыми."

Translation: **The image must be drawn over the WHOLE chest area, with INVISIBLE items in every slot for clickability.**

That means three things must change relative to what we have now:

1. **Use Oraxen Custom-GUI feature** instead of the inventory-title trick.
   The Oraxen docs page is https://docs.oraxen.com/configuration/glyphs/custom-gui — registers a glyph whose ascent puts it into the slot area, and uses negative-shift glyphs to align it pixel-perfectly. Oraxen has built-in helper glyphs `space_-N` for this in `glyphs/shifts.yml`. Then in `menu_title:` you concatenate `<shift_X><image_glyph>`.
   - On 1.20+ servers, negative-spacing is built into vanilla. On 1.16.5 Oraxen ships its `shifts.yml` with `height: -3, -4, -6, -10, -18, -34` etc., which work because they're treated as 1-px wide "characters" with negative height — same effect as negative `space`. They are already defined on this server (`/plugins/Oraxen/glyphs/shifts.yml`, see bundle). Use them.

2. **Make all clickable items in the menu invisible**, so the image shows through.
   - Easiest in Oraxen: add an Oraxen item with `Pack.generate_model: true` + `Pack.parent_model: item/empty` and a fully-transparent texture. That makes the held item visually blank but still has hover-text and click. The Oraxen docs link in the YT description: https://docs.oraxen.com/configuration/glyphs/custom-gui#how-do-i-create-an-invisible-item .
   - Alternative: assign a `nameplates`-style custom model data to an existing material (e.g. `paper:1001`) and ship a 1×1 transparent PNG for that CMD via Oraxen. DM supports `model-data:` in item definitions.
   - All filler glass panes in slots 0,8 (the orange/black "border") should be removed too, or replaced with the same invisible item.

3. **The PNG itself must cover the WHOLE chest interior including slot bezels.**
   The current PNGs are already 168 px wide × (17 + rows×18) tall and already paint the slot grid in dark orange. The render-order issue from §5 is solved automatically once invisible items take the place of the vanilla bevels (the bevels still render but the dark slots in the image cover them; with invisible items there's nothing left on top of the image, so the image *is* the chest interior).

   - 168 px wide is correct (= chest width 176 px minus the 8-px left margin we can't reach because there's no negative-x shift on 1.16.5).
   - Heights 71/107/125 are correct for 3/5/6-row chests.

   **Re-do the PNGs only if you don't like the v4 art** — the v4 dimensions and slot fill are already correct for the "image covers everything" approach. The art lives in `pack_overlays/*.png` in this bundle and in `scripts/gen_combined_glyphs.py`.

## 8. Pitfalls / gotchas

1. **Oraxen reshuffles codepoints on every `oraxen reload all`.** If you add or remove a glyph, every Tamil codepoint may move. Always re-read `assets/minecraft/font/default.json` from the freshly built pack zip before bulk-rewriting `menu_title:`.

2. **`automatically_set_glyph_code: false` is a lie** in this Oraxen version. The `char:` field in our `menus_overlay.yml` is ignored. Don't expect explicit codepoints.

3. **server.properties only re-read on full server start.** Updating it does nothing for already-connected clients; Oraxen's `Player.setResourcePack()` is what actually pushes the pack URL on join. After regenerating the pack you don't need to restart the server — Oraxen will send the new URL automatically. You only need to update `server.properties` for **fallback consistency** (e.g. if Oraxen plugin fails).

4. **Cracked SSSpigot2 quirks**:
   - `ProtocolLib AdvancedPackSender` throws on every join → keep `Pack.dispatch.send_pack_advanced.enabled: false`.
   - `Pack.generation.protection: true` corrupts CRCs → keep it `false`.

5. **`require-resource-pack=false`** vs `=true`: keep it `false`. Setting it `true` kicks anyone who declines, which is hostile during iteration. On `false`, the client falls back to vanilla which is acceptable.

6. **MC 1.16.5 ↔ pack_format**: must be exactly `pack_format: 6` in `pack.mcmeta`. Using `7` (1.17+) causes silent client rejection ("Failed to load").

7. **DON'T touch** `assets/minecraft/textures/gui/container/generic_54.png` or `gui/container/inventory.png`. The user has explicitly forbidden that.

8. **DM 1.14.1 warnings** «Enchantment format 'DURABILITY:1' is incorrect» are pre-existing and unrelated — leave them.
